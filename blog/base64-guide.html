What is Base64 Encoding?

Base64 is a binary-to-text encoding scheme that represents binary data in an ASCII string format. It uses 64 characters (A-Z, a-z, 0-9, +, /) plus = for padding. The primary purpose: reliably transmit binary data over systems designed for text.

Why is Base64 Used?

  • Email attachments (MIME): SMTP was designed for 7-bit ASCII. Binary attachments must be encoded as Base64 to survive email transmission.
  • Data URIs: Embed images, fonts, or other binary data directly in HTML/CSS as data:text/plain;base64,...
  • API payloads: JSON APIs often receive binary data as Base64-encoded strings since JSON doesn't natively support binary.
  • Authentication: HTTP Basic Auth uses Base64 to encode username:password pairs (though this is not encryption — it's easily decoded).
  • Storing binary in text databases: When databases lack BLOB support, Base64 is a common workaround.

How Base64 Works

Base64 processes data in groups of 3 bytes (24 bits):

  • 3 bytes → 24 bits → split into 4 groups of 6 bits each
  • Each 6-bit value (0-63) maps to a character in the Base64 alphabet
  • If input length isn't divisible by 3, = padding is added

Common Use Cases

  • Embedding images in HTML emails: Inline images as Base64 data URIs ensure they display even when external resources are blocked
  • File upload previews: Convert a selected file to Base64 for instant browser-side preview
  • Small file transfer: Encode small configuration files or certificates for text-based transfer
  • Web Crypto operations: Export/import cryptographic keys as Base64-encoded strings

Frequently Asked Questions

Is Base64 encryption?

No. Base64 is encoding, not encryption. Anyone can decode Base64 instantly — it provides no security. Never use Base64 to protect sensitive data.

Does Base64 make data larger?

Yes. Base64 increases data size by approximately 33% (every 3 bytes becomes 4 characters). This is the overhead of making binary data text-safe.
